# V0.5 · 代码工坊（可编辑修复挑战）

本轮在保留 V0.4「选择补丁」副本的基础上，另增导航「⌨️ 代码工坊」。本地单人模式。先通关 JavaScript 森林的「代码侦探」才开放两道可编辑修复题：React 定时器旧闭包、异步搜索结果竞态。

## 玩家流程

1. 打开代码工坊，选择一个题目，阅读故障描述和两个验收目标。
2. 直接在完整 JavaScript 函数中修改代码。页面约 1 秒后自动保存，也可点「保存草稿」。切换题目之前会保存未保存的非空代码。
3. 点击「提交结构检查」：服务端使用 Acorn 仅解析语法树、检查语法和指定代码结构；逐项返回通过/失败。未通过可继续改写并提交；薄弱知识点加入现有记忆队列。
4. 每道题首次通过可得 75 XP。SQLite 事务 + `game_rewards` 唯一事件键确保重复提交/重启不重复发奖。提交记录、草稿和通过状态存数据库。

**判题边界：** 不执行 JavaScript、不运行外部命令、不调用 eval / vm / 子进程；结构检查并不等同于语义正确性、安全审计或真实单元测试。例如包含正确结构但在其他分支做了错误逻辑时，静态规则仍可能判断通过。界面明确告知这一点。任何公网上线、多用户支持都需要先实现账户认证和数据隔离。

## API

- `GET /api/editor`：解锁状态、题目元数据、完成记录、XP；未解锁时不返回题目源代码。
- `GET /api/editor/:id`：题目、故障说明、验收目标、草稿和上次结构检查结果；未解锁返回 409。
- `PUT /api/editor/:id/draft`：`{"source":"..."}` 保存非空、最多 4096 字符的草稿。
- `POST /api/editor/:id/submit`：`{"source":"..."}` 保存提交、反馈和可能的一次性 XP；返回 `checks`、`lastPassed`、`earnedXp`。

示例题号：`counter` 和 `stale-request`。未通过关卡不能提交。不会在首次检查前把正确答案字段下发到 API。

## 验证

```bash
npm install
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

GitHub Actions 在 Node 单元和 HTTP 测试、Vite 生产构建后安装 Chromium 并执行真实浏览器冒烟测试，验证进入工坊、编辑、提交、领取奖励、刷新恢复、地图切换和窄屏入口。浏览器覆盖仍是冒烟范围，尚未涵盖全部五关、心魔、跨天复习等综合 E2E。

技术栈：Node.js >=22.13、React、SQLite、Acorn（仅解析）、Playwright（测试环境）。
